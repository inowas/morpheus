# Security and Git

## Security

- Treat project data as strictly confidential.
- Never log or commit secrets, credentials, tokens, or private keys.
- Do not place customer-specific identifiers in documentation or test output.
- Use test databases and test credentials for tests.
- Do not call external APIs with project data.

## Git

- Work on the migration branch, not directly on `main`.
- Inspect `git status` before editing.
- Stage only files belonging to the current change.
- Do not modify pre-existing untracked files unless explicitly requested.
- Do not edit `.nexus/AGENTS.md`; it is generated by Nexus.
- Commit only after the relevant verification loop is green.
